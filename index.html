The problem

An edited road should change more than pixels.

Appearance-only methods can add rain, snow, a speed hump, or a road depression while replaying the original ego motion. muSync-GS couples each edit to braking, wheel slip, axle load, heave, pitch, path progress, and the rendered camera trajectory.

Visual plausibility alone does not guarantee a physically consistent counterfactual. muSync-GS makes the visual and dynamic branches consequences of the same intervention.

Abstract

Counterfactual driving video with a shared physical cause.

Rare adverse-weather braking and uneven-road events are costly and risky to collect at scale. Existing video and 3D Gaussian editors can change weather appearance or road geometry, but usually leave tire–road interaction, vehicle response, and ego motion disconnected from the edit.

muSync-GS uses precipitation-derived surface state, a shared signed road-elevation profile, and a calibrated tire–vehicle model to synchronize road appearance, friction, braking, wheel slip, normal load, heave, pitch, and camera motion. We evaluate the frozen vehicle response against CarSim, audit brake dive on A2D2, and compare video-level response and controllability on reconstructed Waymo scenes.

Method

One scenario state, synchronized outputs.

The same control variables enter both branches; rendered pixels are never treated as physical measurements.

01

Surface state

Precipitation rate and duration determine water-film or snow state, which controls both road appearance and effective tire friction.

weather → surface → appearance + friction
02

Shared road geometry

A signed road-height profile drives both the visible Gaussian road edit and the front/rear tire-contact excitation.

road profile → edit + axle excitation
03

Trajectory synchronization

Simulated station, heave, and pitch correct the ego-camera pose so the rendered motion follows the predicted vehicle response.

vehicle state → route timing + camera pose

Evidence

Visual control, physical response, and real-vehicle audit.

We separate frozen vehicle-model accuracy, video-response diagnostics, real-vehicle brake-dive consistency, and visual controllability rather than compressing them into a single score.

Frozen-parameter validation

Held-out controls without parameter refitting

The reduced-order model tracks CarSim speed, body pitch, slip ratio, and per-wheel normal load across weather, braking, and road-profile conditions.

  • 0.0273 m/s speed RMSE
  • 0.0590° body-pitch RMSE
  • 0.0101 slip-ratio RMSE
  • 26.61 N per-wheel load RMSE

VGGT-based diagnostics

Motion responds to the counterfactual controls

Weather progress and road-geometry scores are protocol-specific diagnostics, not a single physical-accuracy ranking of video generators.

  • 0.00424 ± 0.00010 normalized-progress RMSE
  • 0.00266 ± 0.00007 progress-aligned lateral deviation
  • 0.352 / 0.396 hump / depression response NRMSE
  • 0.354 / 0.406 rendered state reference, geometry only

The rendered state reference is empirical, not a strict measurement lower bound.

A2D2 brake-dive audit

Complete-drive leave-one-out evaluation

Vehicle-specific calibration is learned from the other two drives and evaluated on the held-out drive, using only brake pressure and onset speed at test time.

  • 14 braking events across 3 drives
  • 0.062° body-pitch RMSE
  • 0.381°/s pitch-rate RMSE
  • 0.901 / 0.560 pitch / pitch-rate correlation

Matched visual protocols

Controllable weather and localized road edits

Rain and snow severity is evaluated separately from localized road editing. Dry-road geometry synthesis is deterministic; precipitation appearance is reported across random seeds.

  • 1.000 / 1.000 rain / snow severity ordering
  • 0.711 localized-edit rate
  • 0.603 temporal mask IoU

Scope

What this study does—and does not—claim.

  • Quantitative video experiments use static or quasi-static Waymo segments.
  • Other agents are replayed rather than counterfactually resimulated.
  • VGGT motion scores are monocular diagnostics with protocol-specific normalization.
  • The rendered state reference is geometry-only and empirical, not a strict measurement floor.
